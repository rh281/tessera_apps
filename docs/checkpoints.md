# Build checkpoints

The brief (section 8) asks for a report at each checkpoint: what was built, the numbers, what was surprising, and what should change in the brief. Honest numbers over good numbers.

## Checkpoint 1: scaffold and `io.py` (2026-10-14)

### Built

- Package scaffold:
  - `pyproject.toml` (hatchling, src layout, `tessera-apps` console entry reserved for the CLI).
  - `ruff.toml` and `mypy.ini`, both copied from `dClimate/tessera-embeddings`.
  - `requirements-lock.txt`, generated by `uv pip compile`.
  - CI on Python 3.12 and 3.13, running ruff, mypy, offline pytest and a lock drift check.
- `src/tessera_apps/io.py`:
  - **Zones.** `zone_for` uses pure six-degree bands.
  - **Reader.** `TesseraReader` reads the anonymous Icechunk store with plain zarr, never Dask. It counts payload bytes and pins or records the snapshot.
  - **Plans.** `plan_aoi` is metadata only. It splits an AOI by nominal zone, so pixels on a zone edge are counted once, and refuses AOIs that are too large, touch too many zones, or are spread too thin.
  - **Reads.** `read_polygon` and `read_bbox` read small AOIs whole. `iter_plan_blocks` streams large ones in chunk-aligned blocks trimmed to the AOI. `read_points` batches points by chunk.
  - **Checks.** Years are checked against `years_complete` before any chunk is read.
- `src/tessera_apps/cache.py`: an optional on-disk chunk cache, namespaced by snapshot.
- Data:
  - `tests/fixtures/caldor_64.npz`: a real 64 x 64 Caldor window, about half burned, covering 2017 to 2025 with every layer.
  - `src/tessera_apps/data/caldor.geojson`: the Caldor demo AOI. It is provisional, see below.
- 164 offline tests in 5 files, running in about 16 s. They pass with read pools of 1, 2 and 16 threads, and with the run pinned to one CPU.

### How it was checked

1. **Pre-build survey.** 11 agents checked the brief against the source repo, the live store and the reference datasets (`docs/prebuild-survey.md`).
2. **Adversarial review.** A review of `io.py` and its tests used four lenses: geometry, store I/O, test quality, and cost. Each finding was re-checked by an independent skeptic. 32 findings were confirmed and 1 was refuted.
3. **Tests from the findings.** Three agents wrote tests for the findings and mutation-tested them. 90 of 92 targeted mutants were killed. The two survivors are equivalent mutants: removing either of the two redundant polygon filters alone changes no output.

### What the review caught

**Bugs fixed:**

- **Lines burned into masks.** An AOI edge lying exactly on a zone edge or on the equator was burned into the mask as a line. This counted pixels twice. Only polygon parts are kept now.
- **Equator points.** Points at exactly latitude 0 returned NaN, because they fell one row past the north group. They are now read from the south group.
- **Older snapshots.** Snapshots before `B6AFRJGX` store `spatial:transform` at the pixel centre, so pinning one shifted the grid by half a pixel. The reader now checks the transform against `spatial:bbox`.
- **Longitude range.** Longitudes outside -180 to 180 (0 to 360 data) silently returned NaN. They now raise an error.
- **Byte estimate.** `estimated_bytes` claimed to be an upper bound but was not. The estimate and the reader now count the same trimmed blocks.
- **Uncounted bytes.** Gap bytes inside merged range fetches were not counted.
- **Memory.** A small AOI made of far-apart parts could allocate a mask of several GB before any check ran.
- **Cache.** A cold cache was 5 to 10 times slower than no cache, and an unnamespaced cache could serve one store's chunks to another.
- **Slow reads.** Layers and point chunks were read one after another.

**Bugs found by the new tests in the fixes themselves, also fixed:**

- **Deadlock.** `read_points` deadlocked once a call touched 16 or more chunks, because nested tasks ran on one thread pool.
- **Byte counter race.** The byte counter lost updates under concurrent sync reads.
- **Late refusal.** `plan_aoi` rasterized earlier zones before refusing a sparse later zone.

### Surprises

- **The brief's dependency floors could not open the store.** The store is in the Icechunk v2 format, so icechunk 1.x fails, and `geotessera` before 0.11 silently reads the legacy v1 model (survey B1, B2). The package pins `icechunk>=2.2,<3` and `zarr>=3.3`.
- **The Caldor AOI crosses into zone 11N.** The Christmas Valley lobe of the scar lies east of 120 W, so checkpoint 1 exercised the multi-zone path.
- **NIFC is unreachable from the build environment.** The Caldor AOI was derived instead from Hansen GFC v1.13 2021 loss. The rule is the largest patch, plus any patch of at least 500 ha within 1 km of it, with the bounding box buffered by 2 km. That patch set covers about 70,700 ha, against Caldor's official 89,775 ha: Hansen records stand-replacing loss only. Replace it with the NIFC perimeter bounding box when the network tier runs.
- **No radar-free pixels in the Caldor AOI in 2020, as the survey predicted.** The radar-regime bias (survey B5) will not show up in the demos, only in general use.

### Changes to the brief

All of these are in `docs/prebuild-survey.md`, "Proposed edits to the brief". The ones that bit at this checkpoint:

1. **Dependency floors.** Use `icechunk>=2.2,<3`, `zarr>=3.3`, `numcodecs[pcodec]>=0.16` and `geotessera>=0.11,<0.12`.
2. **One backend.** This build reads the Icechunk store only, and `geotessera` is not yet a dependency. The Source Coop Zarr copy that `GeoTesseraZarr()` reads by default uses different group names, dimension order, hemisphere convention and chunking (survey S1). Supporting both would mean a normalising layer for no gain at this stage.
3. **"Before any S3 read" should be "before any chunk read".** Checking `years_complete` itself needs a metadata read.
4. **Express the size guard in bytes, not km2.** `AOIPlan.estimated_bytes` now gives an exact count of the chunks the block reader fetches.
5. **Report the snapshot id, not `checkpoint_id`, as the data version.** `checkpoint_id` names the model weights.
6. **Get NIFC (and EFFIS and GMW) access.** The network tier needs an environment that can reach them.

### Not done at this checkpoint

- **Checkpoint 2.** Done next, see below.
- **CLI.** Only `tessera-apps info` exists.

## Checkpoint 2: metrics, export, validation loaders (2026-10-15)

### Built

- **`metrics.py`** is pure numpy and scipy.
  - **Cosine.** `cosine_similarity` computes on int8 directly: the per-pixel scales cancel, so the result is exact. Integer accumulation avoids overflow, and large blocks are processed in strips. On top of it sit `cosine_similarity_map`, `cosine_distance_map` and `cosine_to_vector`.
  - **Means and trajectories.** `mean_embedding` dequantizes and pools across blocks. `trajectory` gives per-pixel similarity to a reference year.
  - **Radar regime.** `same_radar_regime` is the survey B5 guard.
  - **Thresholds and masks.** `otsu_threshold` reports separability and bimodality, for the survey N12 fallback. `clean_mask` applies a 3 x 3 opening and a minimum area. `component_sizes` gives patch sizes, and `area_to_pixels` converts hectares to pixels.
  - **False colour.** `fit_pca` and `pca_rgb` give deterministic PCA colours. The basis can be reused across years, so before and after colours are comparable.
- **`export.py`.**
  - **Rasters.** `write_geotiff` writes a COG through GDAL's COG driver, atomically, and handles NaN and bool nodata. `mosaic_zones` merges per-zone results into one raster: each ground pixel comes from its nominal zone, using GDAL's exact transformer and a seam pass so no holes are left along 120 W.
  - **Tables, JSON and previews.** `write_table` writes parquet and csv, and `write_json` is numpy-safe. `write_preview_png` uses a matplotlib Figure, never pyplot.
  - **Provenance and reruns.** `provenance_record` puts the snapshot id under data provenance and `checkpoint_id` under model provenance (survey S4). It records library versions and the AOI sha256, and drops anything that looks like a credential. `output_paths`, `outputs_current` and `begin_run` make reruns idempotent: outputs are skipped only when `report.json` records the same arguments digest (survey S19).
- **`validate.py`.**
  - **Scoring.** `binary_scores` and `merge_scores` return null, never NaN, on an empty denominator. There are also `confusion_matrix`, `per_class_f1` and `write_validation_json`.
  - **Reference rasters on the AOI grid.** `reference_from_geometries`, `reference_from_file` (the `--reference` option, any CRS) and `reference_from_raster` (windowed, exact transformer).
  - **Loaders.**
    - NIFC (`nifc_perimeters`), from ArcGIS REST, with runtime field discovery and paging.
    - EFFIS (`effis_burnt_areas`), WFS 2.0 with an axis-order guard.
    - Hansen GFC v1.13 (`hansen_loss`, `hansen_forest`, `hansen_valid`, `hansen_layer`). Loss is counted over the year window (a, b], following survey S13.
    - Global Mangrove Watch v3 and v4.1.12 (`gmw_extent`, `gmw_coverage`). Versions are never mixed, and years v3 does not cover raise an error.
    - Natural Earth coastline (`natural_earth_coastline`).
    - USFS FACTS reforestation polygons (`usfs_reforestation`), as a source of restore demo sites.
  - **Caching and errors.** Downloads are cached atomically under `~/.cache/tessera_apps/reference/`. Every remote read has timeouts. An unreachable host raises `ReferenceUnavailableError`, which names the host and says how to supply the data by hand.
- **`demo.py`** loads the bundled demo AOIs: `caldor`, `rondonia` (new, survey S14) and `everglades` (new).
- **Tests and dependencies.**
  - 507 offline tests run in about 60 s, plus 7 network tests (`pytest -m network`).
  - The `[validate]` extra is now empty: validate.py needs only the standard library and GDAL, so `requests` and `owslib` were dropped from the lock.
  - `pyogrio` is declared directly, because validate.py imports it.

### How it was checked

Each module had a builder agent, a correctness reviewer, a test-strength reviewer, a skeptic on every finding, and then a fix pass by the builder. An integration agent then checked the three modules together.

- **Mutation testing at build time.** Builders killed 37 of 37 mutants (metrics), 47 of 47 (export) and 45 of 46 (validate).
- **Confirmed findings.** Reviewers confirmed 36 and refuted 4. All were fixed except one, which belongs to the apps (see below).
- **Notable bugs fixed:**
  - Holes along the zone seam when a mosaic is assembled from blocks.
  - `outputs_current` accepting a validation.json from a run with different arguments.
  - EFFIS GML crashing on an empty page, and EFFIS paging silently stopping at a server-side cap.
  - GMW v4.1.12 picking files from the wrong year.
  - South-up rasters crashing the reference reader.
  - No GDAL HTTP timeouts.
  - Cached GMW files still needing Zenodo to load.
  - Otsu peak memory at about 6 times the input.
  - Explicit masks replacing the AOI mask instead of being ANDed with it.
- **Change outside the three modules.** I gave `cache.py` a single `cache_dir()`, read when called, so chunk caches and reference downloads always share one root. An empty `TESSERA_APPS_CACHE` had made the two diverge.

### Surprises

- **Stable pixels on the 64 x 64 fixture (corrected at checkpoint 3).** On the half-burned fixture window, unburned pixels compared 2020 against 2022 have a median cosine of 0.895. That is a property of a window that sits on the burn edge, not of stable land: across the whole Caldor AOI, land the wildfire app leaves unburned has a median of 0.96, with 83.5% above 0.9 (checkpoint 3). The survey S11 calibration is kept anyway, because it costs nothing and protects places where stable land drifts more.
- **The mosaic needs GDAL's exact transformer.** GDAL's default 0.125-pixel approximate transformer put 2.2% of the 11N pixels at Caldor on a neighbouring source pixel. The exact transformer costs about twice as long when the larger zone is the one being reprojected.
- **Hansen and NIFC disagree in shape.** Hansen 2021 loss covers 13.2% of the Caldor AOI, against 25.3% for the closed Hansen outline, because the scar is patchy inside. This matters for the IoU < 0.6 stop rule at checkpoint 3: a pixel mask scored against a filled perimeter has an IoU ceiling well below 1 (survey S10).

### Changes to the brief and to the apps

1. **Section 5 and 8, network access.** Validation of wildfire (NIFC, EFFIS), wetland (GMW on Zenodo) and the restore demo site (USFS) needs those hosts. Run the network tier where they are reachable, or supply files with `--reference` or `source=`.
2. **Section 3, the `[validate]` extra.** It needs no packages. Keep it empty, or drop it.
3. **Checkpoint 3 design.** On a multi-zone AOI, run `clean_mask` and the minimum-area filter on the mosaic, not per zone, or a scar crossing 120 W is split and its parts dropped (metrics M5).
4. **Checkpoint 3 design.** AND `same_radar_regime` into every compared pair of years (survey B5). Stream means and PCA as per-block sums or samples rather than holding every block in memory.

### Not done at this checkpoint

- The four applications, the CLI commands and the notebooks: checkpoints 3 to 6.
- Live verification of the NIFC, EFFIS, GMW and USFS loaders.

## Checkpoint 3: the wildfire app (2026-10-15)

### Built

- **Shared app framework, `apps/_common.py`.** Deforest, wetland and restore will reuse it.
  - `load_aoi` takes a file in any CRS or a demo name.
  - `prepare_run` plans the AOI, checks every year the app will read against `years_complete` and loads the validation reference, all before any chunk read. It also decides whether to skip: a rerun is skipped only when the arguments digest matches, and the digest includes the resolved store snapshot.
  - `finish_run` writes the report last, with provenance, the bytes read and stage timings.
  - `mosaic_and_clean` cleans masks on the mosaic of all zones, so a scar crossing a zone edge is judged whole.
- **`apps/wildfire.py`**, the brief's section 4.1 as corrected by the survey:
  - Pixels whose radar regime differs between the two years are excluded (B5).
  - The threshold is Otsu, accepted only when the distance histogram also has a real valley. Otherwise it falls back to the 99th percentile of a stable pre-fire pair of years (N12).
  - `fire_year` defaults to `year_b - 1` (N11).
  - Recovery is calibrated against land shown to be unchanged, instead of a fixed 0.9 similarity (S11). That land has a distance at most half the threshold and lies 2 or more pixels from any burn.
  - Validation reports recall inside the reference, the share of the burned mask outside it, and the caveats (S10).
- **CLI:** `tessera-apps wildfire --aoi PATH|demo --year-a --year-b [--validate] [--reference] ...`. Exit code 2 means a usage or precondition error, raised before any read. Exit code 3 means `--strict-validate` failed.
- **Outputs:**
  - `wildfire_<a>_<b>.tif`: bands for distance, burned, and the recovery index for each year.
  - Two PCA false colour COGs, sharing one basis.
  - A summary table with one row per recovery year.
  - A six-panel preview, the report, and the validation JSON.
- **Notebook:** `notebooks/01_wildfire.ipynb`, executed with outputs. It is 1.5 MB.
- **Tests:** 629 offline tests (up from 507), plus a network smoke test on a 290 ha live window.

### Validation and the brief's IoU 0.6 stop rule

NIFC cannot be reached from the build environment, so the burned mask was scored against the Hansen 2021 loss outline bundled with the caldor demo. That is a filled outline of stand-replacing forest loss, not a fire perimeter.

| | |
|---|---|
| IoU | **0.645** (10N 0.643, 11N 0.740) |
| Precision | 0.933 |
| Recall | 0.677 |
| F1 | 0.784 |
| Burned pixels outside the reference | 6.7% |

Nothing was tuned: the threshold is Otsu's, the parameters are the defaults, and the reference was fixed before the run.

The score is limited by recall. The diagnosis:

- **The misses.** 43% of the 2.29M missed outline pixels did not change, so they are unburned islands. 57% changed, but less than the threshold, which fits low to moderate severity burn.
- **Hansen's own pixels.** The app finds 94.8% of Hansen's own 2021 loss pixels, and Hansen loss covers only 51% of the filled outline.
- **The false positives.** 51% are Hansen 2022 loss: delayed mortality or salvage logging inside the 2020 to 2022 window.
- **Moving the threshold does not help.** The distance band from 0.12 to 0.24 holds more pixels outside the outline than missed pixels inside it.

**Against NIFC, the IoU will very likely be below 0.6.** The app finds 51,443 burned ha and the official Caldor perimeter is 89,775 ha. If that perimeter lies inside the AOI, IoU is at most 51,443 / 89,775 = 0.57, whatever the overlap. This is the brief's stop-and-report case. A pixel mask of lasting spectral change cannot match a filled perimeter that includes unburned islands and light burn. That is a limit of the reference, not a threshold to tune. Two ways forward, which are a decision for you:

1. Validate against a severity product instead of a perimeter. MTBS dNBR classes moderate and high are the natural choice for the US, and need mtbs.gov access.
2. Keep NIFC, report recall inside the perimeter as the primary score, and keep IoU as a secondary score with this caveat.

To score against NIFC where services3.arcgis.com is reachable:

```
tessera-apps wildfire --aoi caldor --year-a 2020 --year-b 2022 --validate --fire-name Caldor
```

### How it was checked

One agent built the app and the framework. Three reviewers looked at the method, the framework and CLI, and test strength, and a skeptic verified each finding. Reviewers confirmed 29 findings, none were refuted, and all were fixed, with 59 mutants used to prove the new tests. A final agent ran the demo live, built and executed the notebook, and reran every check.

Notable fixes:

- **The recovery reference was contaminated.** It held burned land just under the threshold, which inflated recovery.
- **The bimodality check read the density at Otsu's threshold, not at the valley floor.**
- **A demo name lost to a directory with the same name.**
- **Shapefile edits did not change the digest.** Editing a shapefile's `.prj` or `.dbf` left the AOI digest unchanged.
- **A malformed `--reference` crashed late.** It was only parsed after the whole stream was read.
- **An unwritable `--out` failed late**, after every read.
- **A failed reference fetch forced a full re-stream on every rerun.** The validation is now redone from the outputs on disk.

### Surprises

- **Otsu's separability flag passes almost anything.** A single normal distribution scores eta 0.64, so the brief's "Otsu on the distance histogram" needs a valley test before a fallback can ever fire.
- **The AOI-wide stable similarity is about 0.96, not 0.895.** The checkpoint 2 figure came from the half-burned fixture window, and the report above is corrected. The brief's 0.9 metric stays near zero at Caldor because burned pixels sit near 0.6, not because stable land is below 0.9.
- **Memory is the scaling limit.** Caldor (28M pixels, 2 zones) peaks at 5.3 GB. A 10,000 km2 AOI would need about 19 GB with today's per-zone arrays. The app warns before any chunk read when its estimate exceeds available memory. Lifting the limit needs windowed COG writes in `export.write_geotiff`.

### Changes to the brief

1. **Section 4.1, the stop rule.** Score burned masks against NIFC by recall inside the perimeter, or use a severity product as the reference. IoU against a filled perimeter is bounded well below 1 by construction.
2. **Section 4.1, recovery.** Replace the fixed 0.9 with the calibrated recovered fraction and recovery index, and keep 0.9 as a secondary metric.
3. **Section 6, the AOI size limit.** Set it by memory as well as km2, or require windowed output writes before allowing 10,000 km2.
4. **Section 8, network access.** The NIFC IoU needs an environment that can reach services3.arcgis.com.
