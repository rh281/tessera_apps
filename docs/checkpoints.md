# Build checkpoints

The brief (section 8) asks for a report at each checkpoint: what was built, the numbers, what was surprising, and what should change in the brief. Honest numbers over good numbers.

## Checkpoint 1: scaffold and `io.py` (2026-10-14)

### Built

- Package scaffold:
  - `pyproject.toml` (hatchling, src layout, `tessera-apps` console entry reserved for the CLI).
  - `ruff.toml` and `mypy.ini`, both copied from `dClimate/tessera-embeddings`.
  - `requirements-lock.txt`, generated by `uv pip compile`.
  - CI on Python 3.12 and 3.13, running ruff, mypy, offline pytest and a lock drift check.
- `src/tessera_apps/io.py`:
  - **Zones.** `zone_for` uses pure six-degree bands.
  - **Reader.** `TesseraReader` reads the anonymous Icechunk store with plain zarr, never Dask. It counts payload bytes and pins or records the snapshot.
  - **Plans.** `plan_aoi` is metadata only. It splits an AOI by nominal zone, so pixels on a zone edge are counted once, and refuses AOIs that are too large, touch too many zones, or are spread too thin.
  - **Reads.** `read_polygon` and `read_bbox` read small AOIs whole. `iter_plan_blocks` streams large ones in chunk-aligned blocks trimmed to the AOI. `read_points` batches points by chunk.
  - **Checks.** Years are checked against `years_complete` before any chunk is read.
- `src/tessera_apps/cache.py`: an optional on-disk chunk cache, namespaced by snapshot.
- Data:
  - `tests/fixtures/caldor_64.npz`: a real 64 x 64 Caldor window, about half burned, covering 2017 to 2025 with every layer.
  - `src/tessera_apps/data/caldor.geojson`: the Caldor demo AOI. It is provisional, see below.
- 164 offline tests in 5 files, running in about 16 s. They pass with read pools of 1, 2 and 16 threads, and with the run pinned to one CPU.

### Numbers

`scripts/checkpoint1_caldor.py` reads the Caldor AOI for 2020. It ran from this build container, which is outside `us-west-2`, against snapshot `B6AFRJGX5XQC0A716PA0`.

In the second run the reader read less but counted more. It read less because blocks are now trimmed to their AOI chunks. It counted more because the gap bytes inside merged range fetches are now included. It was faster because layers and years are fetched concurrently.

`read_points` on 40 random Caldor points touching 38 chunks read 306 MB in 6.9 s. That is 8.04 MB per chunk, matching the survey's 8.1 MB per pixel read.

### How it was checked

1. **Pre-build survey.** 11 agents checked the brief against the source repo, the live store and the reference datasets (`docs/prebuild-survey.md`).
2. **Adversarial review.** A review of `io.py` and its tests used four lenses: geometry, store I/O, test quality, and cost. Each finding was re-checked by an independent skeptic. 32 findings were confirmed and 1 was refuted.
3. **Tests from the findings.** Three agents wrote tests for the findings and mutation-tested them. 90 of 92 targeted mutants were killed. The two survivors are equivalent mutants: removing either of the two redundant polygon filters alone changes no output.

### What the review caught

**Bugs fixed:**

- **Lines burned into masks.** An AOI edge lying exactly on a zone edge or on the equator was burned into the mask as a line. This counted pixels twice. Only polygon parts are kept now.
- **Equator points.** Points at exactly latitude 0 returned NaN, because they fell one row past the north group. They are now read from the south group.
- **Older snapshots.** Snapshots before `B6AFRJGX` store `spatial:transform` at the pixel centre, so pinning one shifted the grid by half a pixel. The reader now checks the transform against `spatial:bbox`.
- **Longitude range.** Longitudes outside -180 to 180 (0 to 360 data) silently returned NaN. They now raise an error.
- **Byte estimate.** `estimated_bytes` claimed to be an upper bound but was not. The estimate and the reader now count the same trimmed blocks.
- **Uncounted bytes.** Gap bytes inside merged range fetches were not counted.
- **Memory.** A small AOI made of far-apart parts could allocate a mask of several GB before any check ran.
- **Cache.** A cold cache was 5 to 10 times slower than no cache, and an unnamespaced cache could serve one store's chunks to another.
- **Slow reads.** Layers and point chunks were read one after another.

**Bugs found by the new tests in the fixes themselves, also fixed:**

- **Deadlock.** `read_points` deadlocked once a call touched 16 or more chunks, because nested tasks ran on one thread pool.
- **Byte counter race.** The byte counter lost updates under concurrent sync reads.
- **Late refusal.** `plan_aoi` rasterized earlier zones before refusing a sparse later zone.

### Surprises

- **The brief's dependency floors could not open the store.** The store is in the Icechunk v2 format, so icechunk 1.x fails, and `geotessera` before 0.11 silently reads the legacy v1 model (survey B1, B2). The package pins `icechunk>=2.2,<3` and `zarr>=3.3`.
- **The Caldor AOI crosses into zone 11N.** The Christmas Valley lobe of the scar lies east of 120 W, so checkpoint 1 exercised the multi-zone path.
- **NIFC is unreachable from the build environment.** The Caldor AOI was derived instead from Hansen GFC v1.13 2021 loss. The rule is the largest patch, plus any patch of at least 500 ha within 1 km of it, with the bounding box buffered by 2 km. That patch set covers about 70,700 ha, against Caldor's official 89,775 ha: Hansen records stand-replacing loss only. Replace it with the NIFC perimeter bounding box when the network tier runs.
- **No radar-free pixels in the Caldor AOI in 2020, as the survey predicted.** The radar-regime bias (survey B5) will not show up in the demos, only in general use.

### Changes to the brief

All of these are in `docs/prebuild-survey.md`, "Proposed edits to the brief". The ones that bit at this checkpoint:

1. **Dependency floors.** Use `icechunk>=2.2,<3`, `zarr>=3.3`, `numcodecs[pcodec]>=0.16` and `geotessera>=0.11,<0.12`.
2. **One backend.** This build reads the Icechunk store only, and `geotessera` is not yet a dependency. The Source Coop Zarr copy that `GeoTesseraZarr()` reads by default uses different group names, dimension order, hemisphere convention and chunking (survey S1). Supporting both would mean a normalising layer for no gain at this stage.
3. **"Before any S3 read" should be "before any chunk read".** Checking `years_complete` itself needs a metadata read.
4. **Express the size guard in bytes, not km2.** `AOIPlan.estimated_bytes` now gives an exact count of the chunks the block reader fetches.
5. **Report the snapshot id, not `checkpoint_id`, as the data version.** `checkpoint_id` names the model weights.
6. **Get NIFC (and EFFIS and GMW) access.** The network tier needs an environment that can reach them.
